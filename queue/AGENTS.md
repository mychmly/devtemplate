# queue：任务与档案

**任务正本是 `.shell/queue/ledger.jsonl`，本区是工具维护的阅读与证据面。** 不直接编辑 task.md、批准基线或已登记回执；所有状态与内容修订经 [队列工具](../tool/queue-usage.md)。本规则与程序共定义格式 v1，程序不读散文来动态改变规则。

## 地址与内容

每件任务固定住在 `tasks/T0001/` 这样的地址。编号由锁内自动分配，永不复用；状态变化不搬目录。

- task.md：当前状态、revision、方案、决定、交付与交接的生成视图。
- approval-*.md：每轮批准时冻结的目标、范围、标准、计划和关系。
- receipt-*.md：经 deliver 登记的原样验证回执，旧件不覆盖。
- legacy-import.md：若从旧候裁记录迁入，保留的原文；不充当机器认证的历史授权。

具体路径以工具成功结果中的 `files` 为准，不猜编号格式。新生成文件不会额外添加文件尾空行；旧基线与封卷保留其原生成版本，工具升级不重写它们。

方案先在任务区外起草，格式见 [方案模板](templates/task.md)。工具读取内容后入账，不要求用户操作临时文件。不把模板本身当任务，也不手动向任务目录塞附件。交付物留在项目原处，以 Git 仓库相对路径及指纹引用。

## 授权与四态

批准来源是用户向 Agent 的明确指令。工具记录授权人、指令依据与代书者，不再要求用户额外签字或重复确认。研究请求不自动扩展为实施许可；“可以做”不等于“结果已经通过”。

| 当前状态 | 可转状态 | 操作与条件 |
|---|---|---|
| 候裁 | 批准执行 | approve；或 create --approve 同笔登记明确授权 |
| 候裁 | 驳回 | cancel，记录用户依据 |
| 批准执行 | 收官 | close，本轮有验证申报 passed 的交付、工件未变、用户明确通过 |
| 批准执行 | 候裁 | revoke，记录用户依据、清空认领与本轮交付资格 |
| 批准执行 | 驳回 | cancel，记录用户依据并释放认领 |
| 收官 | 无 | 整卷封存；补充或纠错新建任务，不复活 |
| 驳回 | 无 | 整卷封存；重提新建任务，不复用编号 |

候裁时可以 revise 整份方案和关系。批准后目标、范围、验收标准和关系冻结；要改先 revoke 再 revise、approve。认领者可用 replan 调整计划，但须留依据且不能借此改验收标准。旧计划和批准版本仍在账上。

## 领取与关系

claim 必须满足：批准执行、无人认领、所有祖先仍批准执行、自身及祖先依赖全部收官、所有孩子已终态。就绪集现算，不维护另一份手写看板。

parent 表示拆分，deps 表示前置；两者不可互代。程序检查缺失引用、自指、祖先后代之间的额外依赖，并在“父等子＋继承依赖”的整体等待关系上拒绝环路。被驳回的前置不算完成。

新增或改变父子归属时，相关父任务须处于候裁，不静默改变在途父任务的成员。父子批准不自动级联；先明确批准父任务，再批准孩子。父任务等待孩子全部终态后领取做集成，自己的交付必须晚于最后一个孩子了结，再等用户验收。

撤销或取消父任务前先处理孩子，或者由用户明确同意后使用 `--tree` 整笔处理子树。子树操作同时核对根任务 revision 与全局 seq；任何并发变化导致拒绝，整组不部分落账。

## 交付、接手与收尾

- deliver 只允许认领者调用，必须有实物引用、回执、摘要与 passed／failed／unverified 的真实申报。申报是证据说明，不是自动验收。
- 工具计算工件指纹；收官时重查当前工件，提交时核对实际暂存版本。历史任务引用的对象可以在后续任务中演进，旧回执与任务卷自身仍不可变。
- 用户未通过验收，在原任务内修改、重验、重新 deliver，不擦掉失败记录。撤销再批准后重新交付，不用旧轮次的输出直接收官。
- handoff 写接手说明但保留认领；release 同时记录接手说明并让出。接手者重读任务、基线与证据再 claim；备忘不会授予新权限。
- 认领者失联不自动抢占任务；用户决定 revoke，再 approve、claim。系统进程锁退出会自动释放，但“任务由谁负责”不会因进程消失自行改写。
- 纠正已封存内容需新任务，并在来源中引用原任务，不把终态任务当成新父任务。

## 一致性与恢复

每次写操作须带刚查询到的 revision 和稳定请求号。过期版本拒绝；同号同输入重试返回已执行，不重复落账；同号不同输入拒绝。

机器账与任务区要同批暂存。任务视图被手改会阻止后续操作；repair 先保留差异到本机恢复目录再重建，不反向解释这些改动。账本本身损坏或与 Git 历史冲突时停止，不凭猜测补历史。

队列规则是机械检查；任务内容是否合理、指令是否确实来自用户、验证是否真实，以及对象写入范围的语义判断仍需 Agent 与用户负责。返回 [公共入口](../AGENTS.md)。
