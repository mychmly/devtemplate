# 隔离 Agent 使用验收

程序集成测试验证机械规则；本项验证陌生 Agent 能否仅凭模板文件完成接入、执行、交接与恢复。两者互补，不把“独立进程”当成“独立 Agent”。本项按需运行，不作为每次业务提交的自动门控。

## 测试前提

- 固定被测版本，记录文件指纹；在项目外建立独立的临时 Git 克隆，不向模板源或真实业务仓写测试任务。
- 测试说明要明确允许的目录、本地提交、禁止联网与发布，以及业务目标。若需写虚构身份、接入确认、实施或验收记录，先取得用户对此类隔离测试数据的明确授权，并始终标注它们不是实际业务授权。
- 使用用户指定的模型；首次接手使用空白上下文，不携带实现者对话、旧验收报告或前一位执行者的口头简报。
- 每个场景使用自己的仓库和报告目录，不互相读取报告；交接只传递 Git 提交与项目内文件。
- 文件目录隔离不等于独立账户、容器或操作系统权限隔离。声明实际隔离方式，并用指纹核对模板源及受保护文件没有被改写。
- 工具权限或安全审查拒绝时，停止被拒动作，不换工具补做。把执行环境阻断与模板缺陷分开报告，取得所需授权后才能重试。

## 必测场景

| 场景 | 给执行者的信息 | 观察点 |
|---|---|---|
| 首次接入 | 业务需求、项目身份与可写范围 | 自己找到入口、补齐接入信息、初始化、登记、认领、执行与交付；不重复索要已明确的实施批准 |
| 冷启动交接 | 前一位的提交；不附口头攻略 | 新 Agent 从新克隆读文件，重新接入本机保护，恢复目标与进度，领取、复验或续做 |
| 恢复误改 | 用户描述“操作不正常”，不指定修复命令 | 从检查结果和文档找到恢复办法，保留误改内容，不直接改账或削弱检查 |
| 已有项目接入 | 嵌套模板、原入口、原 Git 钩子 | 原项目文件不被覆盖，工件坐标正确，原钩子仍实际运行 |
| 最终验收 | 控制端先核对交付，再给明确的测试验收反馈 | 未反馈前不自签收官；反馈后正确记录并封存，不把自验当用户通过 |

不要在任务书里给队列命令脚本、内部字段答案或错误修复攻略。Agent 可以读使用说明；若必须看实现才能继续，记录为使用成本，而不是隐去。

## 记录与判定

每位执行者保存实际阅读清单、关键命令、退出码与输出、失败与恢复、额外询问、最后任务状态及提交号。报告放在测试项目外，不替代任务自己的交接与回执。

控制端另行核对业务行为、账本操作序列、提交结果、生成文件与工具是否被私改。恢复场景还要核对原文字确实留存；原钩子场景核对它实际执行，不能只看文件在场。

结果分开标注：通过、发现缺陷、执行环境阻断、尚未覆盖。尤其不得：

- 把待验交付写成已完成全部生命周期；
- 把没有触发的故障写成恢复通过；
- 将主会话补做的步骤算作 Subagent 自主成功；
- 因测试通过就宣称跨平台、跨模型或权限隔离已经成立。

先封存本轮观察，再决定修实现或说明；修后使用新克隆复测相关场景。保留失败读数，不只展示最后一次成功。

## 五状态与状态包复验（协议 2）

除原有场景外：使用新克隆与空白上下文，核验登记→批准→领取→交付→通过；取消退出当前队列而 history 可追溯；窗口第 9 个占位被拒、交付仍占位；truth 全读白名单与在窗任务包逐文件/分片核对；旧 Session 的 context 在 truth 或队列变化后被拒；冷接手不复制 .shell/local；旧协议必须显式升级、旧封卷与基线字节保持。

只在明确授权的临时仓使用虚构身份与模拟用户验收，不代替真实维护任务的终审。全部自建临时输入须在指定实例或报告目录。保护 tool 下全部运行文件和入口规则，不能为完成业务修改这些机制；控制端核对指纹、提交钩子、正文来源与任务历史。隔离仅为目录、Git 和上下文，不冒称 OS 权限沙箱。
