# gate：检查与门控

本区区分两类检查：默认的队列机械检查，以及 [checks.md](checks.md) 中按项目配置的业务检查。效果评价与趋势分析另住 [eval](../eval/AGENTS.md)。

- 队列检查随工具运行，并由 init 接入 Git 的 pre-commit 与 pre-merge-commit；核对实际暂存账本、历史、视图、封存卷、相关交付指纹及运行态排除。检查异常就拒绝提交，不把崩溃当通过。
- 现有 Git 钩子继续运行；不覆盖其内容或跳过其拒绝结果。保护接线异常时工具拒绝写账。
- 项目业务检查不因写在文件里就自动执行。Agent 按批准方案实际运行，记录原样命令、退出码和结果，缺条件标未验证。
- 调整已批准任务的验收方法，先按任务规则重新确认，不能临时降低标准。
- 本次读数归任务，通过 deliver 登记回执，不把本区改成最新结果账。
- 同权限下钩子可被刻意绕过，机器检查不构成独立安全边界，也不认证用户身份或验证申报的真实性。

修改机械工具后运行本区的 [真实集成测试](test_task_queue.py)，不以规则文案自证。返回 [公共入口](../AGENTS.md)。
