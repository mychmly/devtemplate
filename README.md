# 任务驱动的项目模板

用户专注任务，Agent 负责执行，程序维护队列。项目要求仍是 Markdown；任务账由本地工具维护，并自动生成可读的任务文件。

**不是完整产品运行时：没有新界面、常驻服务、联网调用或自动派发。** 需要 Python 3.10+ 与 Git，不需要第三方 Python 包。接入与命令操作由 Agent 完成，用户无需手工维护状态。

## 开始使用

1. 克隆模板，或按下节合入已有项目。
2. 让 Agent 填写 [项目接入信息](charter/project.md) 与 [目标](truth/goals.md)，由用户核对身份、位置与可写范围。模板本身不提供施工授权。
3. Agent 检查 Python 与 Git，并在模板根执行 `python3 tool/task_queue.py init`，然后执行 `python3 tool/task_queue.py doctor`。只有报告 `protection: ready` 才表示队列接线已就绪。
4. Agent 按 [方案模板](queue/templates/task.md) 起草，使用队列工具登记。用户已说“按此方案实施”时，直接记录这条指令并进入批准执行，不重复请批。
5. Agent 领取、执行、实测、交付；用户通过后记录验收并收官。具体命令与恢复办法见 [工具用法](tool/queue-usage.md)。

克隆不会自动安装 Git 钩子，所以每个新克隆都须接入一次；Agent 可以代做。工具不擅自安装 Python、不创建远端或发布。缺运行条件时明确报“保护未就绪”，不静默退化为人工记账。

## 放进已有项目

先在项目外检查模板，再逐项合入，不整目录覆盖。已有 README、AGENTS.md、.gitignore、LICENSE 与 NOTICE 均保留；入口人工合并，有冲突先请用户决定。原有 Git 钩子会通过接线保留，不直接替换其内容。

同名目录职责冲突时，可将整套模板放入无冲突子目录，在项目原入口链接到模板 AGENTS.md。一个 Git 工作仓只接一套队列；项目位置相对模板根填写，交付工件路径则相对 **Git 仓库根**。现有源码不用搬家。

已有旧 Markdown 任务时，先执行 `migrate --preview`。当前仅自动导入无附件、未认领的候裁任务；已批准、终态或复杂历史会明确拒绝，不能凭散文猜授权。迁移会核对预检指纹并保存原件，详见工具用法。

## 已提供的机械保障

- 写前核对状态、版本、认领、父子与继承依赖，拒绝非法操作。
- 系统文件锁串行写账，自动取号；进程退出会释放锁，不靠用户删除锁文件。
- 稳定请求号防止重复落账；撤销重新批准后必须重新交付与验证。
- 整笔写账，失败区分“尚未落账”和“账已保存、视图待恢复”；不留下半笔子树撤销。
- 生成视图不回写机器账；修复前保留意外差异，不静默丢弃手改内容。
- 命令直接返回可阅读的任务、基线、回执和本批暂存路径；嵌套模板也统一使用 Git 仓库根坐标，不靠 Agent 猜文件名。
- 新生成内容采用干净的结尾格式，旧批准基线与封卷按原版本重建；不为格式修正抹改历史或原样证据。
- Git 提交检查实际暂存内容：账本只增、合法状态、视图一致、封存卷不变、相关工件指纹正确、运行态不入库。

## 不夸大的边界

- 用户授权由 Agent 代书，程序核对有依据，不独立认证用户身份；不要求额外审批界面。
- `passed` 是执行者对验证结果的申报，程序不因此证明业务正确；用户验收仍是另一项记录。
- 保障覆盖正常队列操作与受检提交，不防同权限刻意改工具、伪造合法记录或 `--no-verify`。也不拦截 Agent 任意一次对象文件写入，不机读自由文本范围来宣称权限隔离。
- 只支持同一主工作树的本地队列协作，不支持跨机器多主写账或各 worktree 各自改账；对象并行施工的隔离由执行者另行承担。
- 文件系统须支持本地锁与原子替换。本轮真实测试运行于 macOS；其他平台不据此宣称已验证。
- 用户仍需决定目标、范围和结果是否满意；程序承担可确定性检查的记录维护，不代替价值判断。

## 维护验证

修改队列工具后执行 `python3 -B -m unittest discover -s gate -p 'test_*.py' -v`。测试创建临时 Git 仓，实际跑命令、并发进程、提交钩子与中断恢复，不改当前实例账。业务提交不会全跑这套开发测试。
