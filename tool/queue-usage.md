# 队列工具用法

本页面向代用户操作的 Agent。用户只表达需求、范围与验收判断，不必记命令。所有命令在模板根执行；模板位于子目录时，工具会自己定位 Git 仓库根。

## 接入与查询

```text
python3 tool/task_queue.py init
python3 tool/task_queue.py doctor
python3 tool/task_queue.py status
python3 tool/task_queue.py status T0001
```

init 幂等；新克隆要重新接入本机钩子，机器账与任务历史则从 Git 保留。已有钩子被串接，其他 Git 钩子事件也继续委托原钩子。缺 Git、接线冲突、linked worktree 或已有旧任务时会明确拒绝，不覆盖现物。

输出为 JSON，正常结果 `ok: true`。任务查询给出 revision、ready 与受阻原因；全局 seq 用于核对子树操作。程序执行前可使用 `--root <模板根>` 与 `--wait <锁等待秒数>`，这两个参数放在子命令前。

## 使用返回路径，不猜文件名

init、status、写操作和 repair 的成功结果带 `files`：

- `base` 是 Git 仓库根的绝对路径；其余文件路径都相对此处，而不是模板子目录。
- `ledger` 定位机器账；`tasks` 逐任务列出 `task` 阅读视图、`approval` 最近批准基线、`receipt` 本轮最新交付回执、`legacy` 导入原文；没有相应文件时为 null。
- 写操作的 `stage_paths` 是该操作涉及的队列文件及相关交付工件；init 另列需要保存的接入文件。repair 只列实际恢复、或需从索引移除的路径，不把未登记恢复副本放进暂存清单。status 只定位，不提供暂存清单。

直接使用这些路径阅读、核对和精确暂存，不自行推算编号补零位数。清单不是整个工作树的全部改动，也不是自动暂存或提交授权；你另外编辑的接入信息、目标或业务文件仍须核对 Git 状态，按任务范围一并暂存。其他 Agent 同时写入了共享队列时仍须协调同批提交。

同号重试返回**原操作时点**的文件定位，与第一次响应一致；`current_seq` 可能已更大。此时先查询现状，不把原操作清单误当整个当前工作树的全部待提交内容。

## 写入规则

每次写操作必带：

- `--actor`：当前执行者的可辨识名称；用于归因，不是身份认证。
- `--request`：本次逻辑操作的唯一号，建议 UUID；同一次失败重试保持相同号及相同输入，不重新生成。
- 已有任务另带 `--expect`：刚从 status 读到的 revision。过期就重读并判断，不盲目覆盖。
- 用户决定另带 `--by` 与 `--basis`：授权人及用户明确指令的原文或准确摘要；有消息引用可写入依据，无则不虚构。

## 操作表

| 操作 | 其他参数 | 用途 |
|---|---|---|
| create | `--proposal <文件>`；可选 `--parent <编号>`、重复 `--dep <编号>` | 从完整 Markdown 方案登记候裁任务，编号由工具分配 |
| create --approve | 上述参数加 `--by`、`--basis` | 用户已明确授权实施时，同笔登记并批准，不重复请批 |
| revise 编号 | `--proposal <文件> --basis <原因>`；可选父与依赖参数 | 只在候裁修订；省略关系参数就保留原值，明确清空用 `--clear-parent`／`--clear-deps` |
| approve 编号 | `--by <用户> --basis <指令>` | 保存整份批准基线，进入批准执行 |
| claim 编号 | 无额外参数 | 满足就绪条件时领取；不自动启动 Agent |
| handoff 编号 | `--text <接手说明>` | 写备忘但不释放认领 |
| release 编号 | `--text <接手说明>` | 认领者让出，状态不变 |
| replan 编号 | `--plan <文本文件> --basis <原因>` | 认领者修订计划，范围和标准不动 |
| deliver 编号 | 重复 `--artifact <Git相对路径>`、`--receipt <文件>`、`--verification passed或failed或unverified`、`--summary <摘要>` | 捕获实物指纹，原样登记回执，不自动收官 |
| close 编号 | `--by <用户> --basis <通过依据>` | 核对本轮交付后记录用户通过并封存 |
| revoke 编号 | `--by`、`--basis` | 撤销回候裁并释放认领；再次批准须重新交付 |
| cancel 编号 | `--by`、`--basis` | 取消并封存，不复用身份 |

revoke／cancel 可加 `--tree --expect-seq <全局序号>`。仅在用户明确授权处理整组时使用；整笔操作要么全成功要么全不落账，不暗自扩展批准范围。

方案按 [task 模板](../queue/templates/task.md) 的标题与四节准备，放任务区外；编号、状态、关系和认领不手写。回执按 [receipt 模板](../queue/templates/receipt.md) 填好再传入；大文件不要塞入账本，文本输入上限 1 MiB。

工件参数相对 **Git 仓库根**，不是模板根或调用者临时目录。只接本仓普通文件，不跟随符号链接，也不接队列自身或 Git 内部文件。对象在其他仓时，可交付本仓的引用说明，写清外部版本与核对方法；工具只核该说明文件，不假称验证了外部实物。

## 提交

由 Agent 同批暂存 `.shell/queue/`、`queue/tasks/` 与相关交付工件；初始化或工具改动时连同相关配置、工具一起暂存。不要整体暂存 `.shell/local/`。提交检查读取索引 blob，不以工作副本正确来掩盖错误暂存。

队列写入不自动提交或推送。共享工作树的提交仍须协调；本工具不提供对象文件隔离。历史追加以 Git HEAD 为持久比较基线，不宣称能识别一次绕过正常工具、又同步伪造全部未提交记录的行为。

## 错误与恢复

- `ok: false` 表示未完成请求；正常拒绝退出 1。按 code 与 message 处理，不只看退出码。
- `committed: true`／`committed_pending` 表示机器账已保存、视图待恢复，退出 2；用**原请求号和原输入**重试，或运行 repair，不再次创建逻辑操作。
- 下次命令会核对未完成事务：落账前中断则保留旧账；已落账则重建投影。锁由操作系统持有，进程退出自动释放；磁盘上的 queue.lock 不应手工删除。
- 手改视图、回执或放入未登记文件时：先运行 `python3 tool/task_queue.py repair`。意外差异保存到 `.shell/local/recovery/`，之后从账本重建；不会把手改状态写回账。
- 账本损坏、来源指纹不符或 Git 历史被改写时，工具停止。先保留现物，再由 Agent 核对 `.shell/local/last-good.jsonl` 和 Git；不得为消除报错凭空补授权或静默丢弃历史。
- 保护钩子缺失时先 init 核对。接入后若被其他工具切换到陌生 hooksPath，init 不擅自覆盖；由 Agent 核对两套接线，再决定合并。

缓存与恢复副本不是正本。不要删除恢复差异来假装从未发生问题；用户不需要手工读机器账，Agent 应把问题与可恢复范围说明白。

## 旧版 Markdown 候裁任务迁移

先运行 `python3 tool/task_queue.py migrate --preview`，拿到 source_sha256。它只预检，不写账或安装钩子。用户同意迁移后，运行 migrate 并提供 `--expect-source <该指纹> --actor <执行者> --request <唯一号> --by <用户> --basis <迁移指令>`。

目前只自动导入旧版头部为候裁、未认领且无附件的任务；保留编号、原文、父子与依赖，并备份被替换的旧视图。迁移授权只允许转换记录，不批准任务实施。已批准、终态、附件复杂或格式不明者拒绝自动导入，须另做明确核对，不能据散文猜历史。

## 保障边界

机械约束覆盖队列与受检提交，不独立认证用户身份、不验证自然语言指令的全部含义、不自动执行任意业务验收，不拦截所有对象写入。同权限刻意绕过不在保证内。格式当前为 v1；升级格式和转换旧历史须另行设计，不直接改账凑兼容。

### 生成格式兼容

账本头仍为 v1，原有行不重写。新事件携带 `projection_version: 2`，仅规范生成器自己的文件尾换行；未声明的旧事件按版本 1 重建。每份批准基线使用它建立时的版本，旧封卷不会因工具升级改字节。

原样回执与导入原文不作格式清理；其中属于用户原文的空白不因本次修复被抹除。旧基线本来存在的尾空行也保留，不为消除历史样式提示破坏封卷。旧工具不识别新增事件字段时会拒绝读取，不能降级旧工具或删字段绕过；使用更新后的工具。
