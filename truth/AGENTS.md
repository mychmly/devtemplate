# truth：项目长期要求

本区回答“项目要做成什么”，不回答“某件任务进行到了哪里”。

- 起步只填写 [goals.md](goals.md)。确实需要时，再添加设计、架构或领域规则；不要预建空文档树。
- 已确认的要求与尚待决定的问题分开写；草案不能被当成用户已批准的要求。
- 项目要求发生变化时，先取得用户明确同意，在任务里记录决定，再更新此处；文档链接到决定所在任务，不复制整段裁决。
- 保留最后复核日期。复核节奏由项目自行决定，不默认承诺自动过期提醒。
- 临时方案、验证证据与交接说明放任务卷；外部文章放 reference（若保留该区）。

本区文档是直接编辑的正本，不是生成视图。返回 [公共入口](../AGENTS.md)。
