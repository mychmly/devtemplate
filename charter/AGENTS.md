# charter：协作边界

本契约保存跨任务、跨区域的常设协作规则；区域专属规则归该区 AGENTS.md。不另建项目接入表，不保存任务进度或项目设计。

## 基本约定

1. **授权归用户。** Agent 可以起草、记录、执行已批准的范围；不得自行批准自己的任务或验收。用户指令不明确时，问清相关部分，不从备忘、示例或参考材料推导授权。
2. **一件事实只维护一处。** 跨区常设边界在本契约，工作对象位置与对象专属规则在 object/AGENTS.md；单次范围、批准与验收依据归任务；长期目标在 truth；任务现状在 .shell/queue/ledger.jsonl，task.md 是生成视图；必须通过的检查方法在 gate，效果评价与比较方法在 eval；执行结果在任务记录或其回执。窗口容量与 truth 白名单的配置界面在 config.json，初始化后通过 config 命令维护，历史写入同一机器账；状态包只转送白名单 truth 与在窗任务包，不是第二份正本。别另建一份手动同步的状态看板。
3. **按任务工作。** 任务生命周期以 [队列规则](../queue/AGENTS.md) 为准。范围外的问题只登记提案，不顺手实施。规则、配置、文档的改动也可以是任务，但任务内部的微小步骤不必另立任务。
4. **共享写入分两类。** 队列由工具加锁串行写，多位 Agent 经同一主工作树的入口操作，不手工取号或改账。区域契约与对象文件的修改仍须协调；Git 分支本身不提供队列隔离。
5. **事实与判断分开。** 写明实际做了什么、证据在哪、哪些没有验证。Agent 自验标为“未独立验证”；不同会话不当然等于独立证据。
6. **敏感内容不入记录。** 只写凭据的名称或获取说明，不写密钥值。文件修改、工具调用、联网、花费和发布仍受当前用户及执行环境的授权边界约束。
7. **规则也有边界。** 队列工具与提交检查提供机械拒绝，但不是同权限下不可绕过的安全边界。用户授权由 Agent 代书，不独立认证来源；业务正确性与自然语言范围不由程序替人判断。发现职责冲突或权限不明时暂停相关操作并澄清。

## 修改本区

接入时先核对已有契约。用户确认的跨区常设读写边界、禁止事项与外部动作审批要求补入本契约；仅适用于某区的约定写入该区契约，不在此复写。没有额外约定时无需填占位表。安装、联网、费用、推送或发布等动作未明确授权时，不视为允许。

新增或变更常设规则须有用户明确同意，并在对应任务记录中链接依据；用户已经明确的要求不重复请批。不要把一次任务授权或例外自动改成永久权限。

用户当前明确指令和执行环境的上级约束优先；不得用模板绕过它们。若用户批准了持续性的规则变化，再更新本区，使下次接手的人读到同一套要求。
