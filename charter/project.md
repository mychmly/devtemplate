# 项目接入信息

填写后由用户核对。未知值写“待确认”；未确认批准人、项目位置和可写范围前，不开始项目施工。

| 项目 | 值 |
|---|---|
| 项目名称 | 待填写 |
| 任务批准与最终验收人 | 待填写：用户姓名或稳定称呼，不填 Agent |
| 环境文档维护者 | 待填写：负责协调非队列文档的用户或 Agent；队列写入由工具加锁 |
| 项目位置 | 待填写：相对模板根目录的路径；新项目可用 `object/`，同根可填 `.`，已有项目填原位置，不强制搬源码 |
| 允许修改的范围 | 待填写：相对上述项目位置的目录或文件；不要只写“全部” |
| 禁止读取或修改的位置 | 待填写：没有则明确写“无”；不要记录秘密内容 |
| 版本控制与基线方式 | 待填写：例如 Git；不用版本控制时说明如何保存批准版本与修改历史 |
| 外部动作的审批要求 | 待填写：安装依赖、联网、费用、推送、发布等；未说明不视为授权 |

## 接入核对

- 原有项目规则是否已合并、有无未解决冲突：待填写。
- 用户确认人、时间及可追溯的依据：待填写。

项目目标写在 [truth/goals.md](../truth/goals.md)，不要在这里重复。维护者变更在相关任务中记下依据，再修改本表。
